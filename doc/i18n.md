# 多语言规范

项目使用 [next-intl](https://next-intl.dev) 实现国际化，支持中文（默认）和英文。

## 目录结构

```
app/_lib/i18n/
├── messages/
│   ├── zh-CN.json      # 中文翻译
│   └── en.json          # 英文翻译
├── navigation.ts        # 多语言路由导航
├── request.ts           # 服务端 locale 检测
└── routing.ts           # 路由定义（支持的语言、默认语言）
```

## 前端：页面 & 组件

### 在 Server Component 中使用

```tsx
import { getTranslations } from 'next-intl/server'

export default async function Page() {
  const t = await getTranslations('Namespace')
  return <h1>{t('title')}</h1>
}
```

### 在 Client Component 中使用

```tsx
'use client'
import { useTranslations } from 'next-intl'

export default function Component() {
  const t = useTranslations('Namespace')
  return <p>{t('description')}</p>
}
```

### 添加新翻译

1. 在 `zh-CN.json` 和 `en.json` 的同名命名空间下添加 key-value 对
2. tsx 中通过 `t('key')` 引用

### 添加新语言

1. `routing.ts` 的 `locales` 数组追加新 locale（如 `'ja'`）
2. `app/_lib/i18n/messages/` 下新建 `ja.json`
3. 如需前端切换，在语言选择器中加入对应选项

## 统一翻译体系

所有翻译（前端页面、API 错误、邮件模板）统一存放在 next-intl 的 JSON 文件中：

```
app/_lib/i18n/messages/
├── zh-CN.json      # 中文（带 ApiError、Email 命名空间）
└── en.json          # 英文
```

### 后端读取方式

后端通过 `@/app/_lib/i18n/loader` 读取同一份 JSON：

```ts
import { loadMessages, t } from '@/app/_lib/i18n/loader'

// 方式一：加载整个命名空间
const msgs = loadMessages('zh-CN')
msgs.ApiError?.UNAUTHORIZED  // → "未登录"

// 方式二：直接取单条
t('en', 'ApiError', 'RATE_LIMITED', '回退文本')  // → "Too many requests..."
```

### 添加新翻译

只需在一个地方改 —— 在 `zh-CN.json` 和 `en.json` 的对应命名空间下添加 key 即可。

### 在其他后端逻辑中获取当前语言

```ts
import { detectLocaleFromRequest } from '@/app/_lib/locale'

const locale = detectLocaleFromRequest(request)
if (locale === 'en') {
  // 发送英文邮件等
}
```

> `detectLocaleFromRequest` 定义在 `app/_lib/locale.ts`。

## 语言切换逻辑

| 场景 | 语言来源 | 默认值 |
|------|---------|--------|
| 前端页面 | URL locale (`/en/chat` → en, `/chat` → zh-CN) | `zh-CN` |
| API 错误消息 | `Accept-Language` 请求头 | `zh` |
| 邮件 | 由调用方根据用户偏好传入 | `zh` |

- 前端 URL 路由：`localePrefix: 'as-needed'` — 中文无前缀，英文加 `/en`
- 后端 API：从 `Accept-Language` 头解析，不支持的语言回退中文
